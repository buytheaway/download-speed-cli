# download-speed-cli

Небольшая CLI-утилита для измерения скорости скачивания тела HTTP-ответа.
При успешном запуске выполняет ровно 10 последовательных GET-запросов
к одному URL. Каждый ответ полностью читается перед следующим запросом.
Файл не сохраняется: данные читаются чанками по 64 KiB, в памяти остаются
только текущий чанк и результаты измерений.

## Требования

- Python 3.11 или новее.
- `requests` для HTTP-запросов; `argparse` входит в стандартную библиотеку.
- `pytest` для запуска тестов.

## Установка

Откройте терминал в каталоге проекта.

Windows (PowerShell):

```powershell
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Если политика PowerShell запрещает активацию, можно использовать Python
окружения напрямую:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

Команды предполагают, что выбранный интерпретатор соответствует требованиям.
В некоторых дистрибутивах Linux для создания окружения нужен пакет `python3-venv`.

## Запуск

Windows (после активации окружения):

```powershell
python speed_test.py "https://example.com/file.bin"
```

Windows без активации:

```powershell
.\.venv\Scripts\python.exe speed_test.py "https://example.com/file.bin"
```

Linux (после активации окружения):

```bash
python speed_test.py 'https://example.com/file.bin'
```

Замените адрес на доступный HTTP/HTTPS URL файла. Адрес в примере — шаблон,
наличие файла по нему не предполагается. Кавычки нужны для URL с `&` и другими
специальными символами оболочки. Справка: `python speed_test.py --help`.

## Расчёт и единицы измерения

Время измеряется в секундах через `time.perf_counter()`: таймер запускается
перед GET и останавливается после полного чтения и закрытия ответа. Он
учитывает установление соединения, если оно требуется, ожидание сервера
и скачивание тела. Объём — сумма `len(chunk)` для чанков из `iter_content()`;
заголовок `Content-Length` для расчётов не используется.

Отправляется `Accept-Encoding: identity`. Считаются фактически прочитанные
байты тела ответа **после декодирования** библиотекой `requests`, включая
распаковку поддерживаемого сжатия, если сервер его всё же применил.
Декодирование текста не выполняется. Это не объём сетевого трафика:
HTTP-заголовки, TLS, TCP/IP и прочие накладные расходы не учитываются.

- `байт` — объём прочитанного тела ответа; 1 байт = 8 бит.
- `KiB` — 1024 байта.
- `Mbps` — мегабиты в секунду; 1 Mbps = 1 000 000 бит/с.
- Время и скорость выводятся с тремя знаками после точки. Расчёты используют
  исходные значения без округления.

```text
total_bytes = сумма прочитанных байтов всех 10 ответов
total_seconds = сумма времени всех 10 запросов
average_seconds = total_seconds / 10
average_mbps = total_bytes * 8 / total_seconds / 1_000_000
```

Скорость отдельного запроса считается по той же формуле для его объёма
и времени. Итоговая скорость вычисляется по общим объёму и времени,
а не как среднее арифметическое десяти скоростей. В суммарное время
не входят вывод в консоль и паузы между запросами.

## Ошибки и ограничения

URL проверяется до открытия сессии. Поддерживаются схемы HTTP/HTTPS
и успешные ответы 2xx. Перенаправления отключены: ответ 3xx считается
ошибкой, нужно передать конечный URL. Так перенаправления не создают
дополнительных GET-запросов. Автоматические повторные попытки не добавляются.

Таймаут подключения — 5 секунд, чтения — 30 секунд. Таймаут чтения ограничивает
ожидание очередных данных, а не общую длительность скачивания: медленная,
но непрерывная передача может длиться дольше 30 секунд. Общего ограничения
времени теста нет; прервать запуск можно через `Ctrl+C`.

При HTTP-ошибке, таймауте, обрыве соединения или ошибке чтения тест сразу
останавливается. Уже завершённые измерения могут оставаться в консоли,
но итоговая статистика выводится только после всех десяти успешных запросов.
Ответы и сессия закрываются контекстными менеджерами, в том числе при ошибке.
Коды завершения: `0` — успех, `1` — ошибка запроса, `2` — ошибка аргументов,
`130` — прерывание пользователем.

Результат зависит от удалённого сервера, размера файла, задержки и состояния
сети, кэширования, прокси и повторного использования соединения одной
`requests.Session`. Первый запрос может включать DNS, TCP и TLS, а следующие
могут использовать готовое соединение. Маленькие ответы особенно чувствительны
к задержке. Пустое тело допустимо и даёт нулевую скорость.

Это не измерение максимальной пропускной способности интернет-канала.
Тест показывает скорость получения конкретного ресурса в текущих условиях.
Учитывайте, что файл скачивается десять раз, расходуя трафик и ресурсы сервера.

## Тестирование

Установите зависимости разработки в созданное окружение и запустите pytest
из корня проекта (одинаково для Windows и Linux):

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

Без активации окружения на Windows:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
```

Тесты заменяют HTTP-сессию, ответы и часы там, где важны точные значения.
Реальные сетевые запросы запрещены общей фикстурой. Проверяются формула
скорости и среднее время, подсчёт чанков независимо от `Content-Length`,
десять последовательных GET, порядок чтения и закрытия ответов, параметры
запросов, HTTP-ошибки, перенаправления, таймауты, обрывы тела и проверка URL.
